Your containers, reachable by hostname.

aka is your development proxy for docker. Set VIRTUAL_HOST on a container, run aka up, open http://that-host.docker. HTTP vhosts, TLS passthrough and raw TCP routes — a Rust spiritual successor to dory, built on angie.

Install

curl -fsSL https://raw.githubusercontent.com/freshbrewlabs/aka/main/install.sh | bash

Needs git, a running Docker, and Rust (cargo) — the script checks all three. Builds the managed proxy/DNS images, installs the aka binary into ~/.cargo/bin, writes a commented ~/.aka.toml. Nothing needs sudo. Pin a version with AKA_REF=v1.2.3; re-run any time to update.

Quick start

# one-time: passwordless sudoers rule so `aka up` never prompts
aka install-sudo-rule

# any running container with VIRTUAL_HOST is routed automatically
docker run -d -e VIRTUAL_HOST=demo nginx

aka up
curl http://demo.docker          # -> nginx welcome page
aka status

What it does

http / https vhosts

Host-header routing on :80 with websocket upgrades; proxy to HTTPS backends when you set VIRTUAL_PROTO.

tls + tcp routes

SNI passthrough on :443 and raw TCP ports published on the host — redis-cli -h cache.docker just works.

Multiple TLDs

.docker, .test, whatever you like — each domain and all its subdomains resolve to your proxy.

No sudo, no prompts

One audited sudoers rule lets aka manage /etc/resolver entries itself. Remove it any time.

dory-compatible

Same VIRTUAL_HOST / VIRTUAL_PORT / VIRTUAL_PROTO variables and labels — existing containers need no changes.

Zero-restart discovery

A daemon watches docker events; new containers are routed live, no proxy reload, no container restarts.

Commands

aka up start dns + proxy + host resolver aka down stop everything, clean up resolver entries aka status container states, daemon health, route table aka routes discovered routes (--json) aka logs follow dns / proxy container logs
